## PHASE 1 — Embedded Knowledge

### 1A — Product Knowledge (NetSuite Modules)

**Subsidiary Structure:** NetSuite supports OneWorld multi-subsidiary management. A parent subsidiary can have multiple child subsidiaries. Each subsidiary has its own COA, currency, and reporting period. Consolidation across subsidiaries is standard. Subsidiaries are assigned at transaction level.

**Location:** Physical and virtual locations within a subsidiary. Used to track inventory, allocate expenses, and segment reporting. One location can be an inventory location (warehouse) or an administrative location.

**Department:** Organisational segment for reporting and classification. One department can be linked to multiple subsidiaries. Used in transactions for segmented P&L reporting.

**Class:** Optional reporting dimension. Used for project/non-project classification or product line grouping. Appears on all transaction lines.

**Discipline:** Custom segment (conditional). Created as a custom field or custom segment in NetSuite for additional classification (e.g. non-projects, projects sub-types).

**Dashboard and Reminders:** Standard dashboards configurable per role. Portlets include KPIs, transaction lists, reminders, saved searches. Rapid demonstrates dashboard customisation during CRP session.

**Role and Permissions:** NetSuite is role-driven. 50+ standard roles available. Custom roles can be created. Multi-subsidiary users (e.g. Finance team) get multi-subsidiary access. Other users are restricted to specific subsidiaries. Administrator Role has full access.

**Customer Master:** Stores all customer records with company info, contacts, billing/shipping addresses, financial settings (payment terms, credit limit, currency, receivables account), tax registration, and custom fields.

**Vendor Master:** Stores vendor records with contact info, subsidiaries, tax codes, payables account, payment terms, and custom fields.

**Employee Master:** HR record with personal info, job info (type, status, supervisor), expense/purchase limits, emergency contacts, and NetSuite access/role assignment.

**Design to Build (Inventory):** Item master with types (Inventory, Non-Inventory, Service, Kit, Assembly). Item records carry costing method, pricing, UOM, COGS/asset/income accounts. Transfer Orders, Inventory Adjustments, and Inventory Counts are sub-features.

**Item Types in NetSuite:** Description, Discount, Kit/Package, Non-Inventory, Other Charge, Service, Assembly (if Manufacturing enabled), Inventory Item (if Inventory enabled).

**Project Management:** Projects linked to customers (or standalone). Sub-projects supported. Resource allocation, time tracking, project billing available.

**CRM (Customer Relationship Management):** Lead → Prospect → Customer pipeline. Manage Leads, Prospects, Contacts, Opportunities, Estimates. Activity tracking (calls, tasks, events).

**Order to Cash:** Sales Order → Order Fulfillment → Customer Invoice → Customer Payment. Revenue Recognition available as a sub-feature (deferred revenue, recognition templates, schedules).

**Return to Credit:** Return Authorization → Credit Memo → Customer Refund.

**Procure to Pay:** Purchase Requisition → Purchase Order → Item Receipt → Vendor Bill → Vendor Bill Payment. Blanket POs and Purchase Contracts are optional sub-features.

**Return to Debit:** Vendor Return Authorization → Vendor Credit.

**SAML Single Sign-On:** NetSuite supports SAML 2.0 SSO with identity providers (e.g. Azure AD, Okta). Configured at account level. Users mapped by email.

**Manage Fixed Asset:** Automated acquisition, depreciation (multiple methods), revaluation, disposal. Fixed assets opposed to current assets; useful life >1 year. Accrual-basis tracking.

**Record to Report:** COA, currencies, payment terms, tax codes/rates, journal entries, bank transfers, write check, bank reconciliation, amortisation, expense allocation, expense reporting, budgets, period close, foreign currency revaluation, reports.

**Data Migration:** Rapid migrates data as of cut-off date using client-supplied data in Rapid's templates. Standard scope: Customer Master, Vendor Master, Item Master, Employee Master, COA, Subsidiary Structure, Open AR, Open AP, Opening Balances.

def add_custom_style(doc, style_id, name, base_name, font_name=None,
                     font_size=None, bold=None, color=None,
                     space_before=None, space_after=None, line_spacing=None):
    """Create a custom paragraph style if it doesn't exist."""
    styles = doc.styles
    try:
        return styles[name]
    except KeyError:
        base = styles[base_name] if base_name in [s.name for s in styles] else styles['Normal']
        style = styles.add_style(name, 1)  # 1 = WD_STYLE_TYPE.PARAGRAPH
        style.base_style = base
        if font_name:
            style.font.name = font_name
        if font_size:
            style.font.size = Pt(font_size)
        if bold is not None:
            style.font.bold = bold
        if color:
            style.font.color.rgb = RGBColor.from_string(color.lstrip('#'))
        pf = style.paragraph_format
        if space_before is not None:
            pf.space_before = Twips(space_before)
        if space_after is not None:
            pf.space_after = Twips(space_after)
        return style

def add_table(doc, headers, rows, col_widths_dxa=None):
    table = doc.add_table(rows=1, cols=len(headers))
    table.style = 'Table Grid'
    # Header row
    hdr_cells = table.rows[0].cells
    for i, h in enumerate(headers):
        hdr_cells[i].text = h
        # Shade header cell #D9D9D9
        tc = hdr_cells[i]._tc
        tcPr = tc.get_or_add_tcPr()
        shd = OxmlElement('w:shd')
        shd.set(qn('w:val'), 'clear')
        shd.set(qn('w:color'), 'auto')
        shd.set(qn('w:fill'), 'D9D9D9')
        tcPr.append(shd)
        run = hdr_cells[i].paragraphs[0].runs
        if run:
            run[0].bold = True
    # Set column widths
    if col_widths_dxa:
        for i, cell in enumerate(table.rows[0].cells):
            if i < len(col_widths_dxa):
                tc = cell._tc
                tcPr = tc.get_or_add_tcPr()
                tcW = OxmlElement('w:tcW')
                tcW.set(qn('w:w'), str(col_widths_dxa[i]))
                tcW.set(qn('w:type'), 'dxa')
                tcPr.append(tcW)
    # Data rows
    for row_data in rows:
        row_cells = table.add_row().cells
        for i, val in enumerate(row_data):
            if i < len(row_cells):
                row_cells[i].text = str(val)
    return table

def add_page_number_field(run):

    run._r.append(instr)
    fld2 = OxmlElement('w:fldChar')
    fld2.set(qn('w:fldCharType'), 'end')
    run._r.append(fld2)

## PHASE 5 — Validation Checklist

Before delivering the document, verify all items below:

**Content integrity:**
- [ ] No prior-client identifiers survive (no "FRP/Altrad", "Knorex", "UEMS", account number "9896142")
- [ ] Introduction paragraphs reproduced verbatim (including two spaces before "The Statement of Work determines the scope.")
- [ ] All BLOCKING MOM fields populated; no invented/estimated BLOCKING values
- [ ] Revenue Recognition boilerplate verbatim (if in scope)
- [ ] Item Receipts boilerplate verbatim
- [ ] Acceptance clause names Rapid e-Suite Implementation Services and client; Delivery Date present
- [ ] No section is empty (every included section has content or a gap marker)
- [ ] Out-of-scope sections are fully omitted (no empty stubs)
- [ ] Gap markers are plain NoSpacing paragraphs starting with `*` (not bullets, not headings)
- [ ] No KB-internal identifiers (file names, KB codes) appear in the document
- [ ] Data migration paragraph lists only in-scope data entities
- [ ] MOM action items not treated as scope commitments

**Format integrity:**
- [ ] Page size is US Letter (8.5 x 11 in)
- [ ] Document body font is Calibri 11pt
- [ ] RapidHeading1 style: 16pt bold #4F81BD, applied to all top-level section headings
- [ ] RapidHeading11 style: 12pt #C00000, applied to all sub-section headings
- [ ] All table header rows shaded #D9D9D9
- [ ] DOCX contains `rapid_esuite_logo.png` in header (left side)
- [ ] DOCX contains `header_banner.png` in header (right side)
- [ ] Footer pattern: `[[CLIENT]] - Business Requirement Document       [PAGE]`
- [ ] Cover page has Rapid logo at bottom, client name centred in title block
- [ ] Field detail tables include ALL rows (Customer Master: 75 data rows; Vendor Master: 50; Employee Master: 41; Item Master: 42)
- [ ] No field detail table rows truncated or omitted

**Output:**
- [ ] File saved to correct output directory
- [ ] Format matches operator request (docx / pdf / both)
- [ ] TOC has been generated or a placeholder field is present (update required in Word via F9)
