## PHASE 1 — Embedded Knowledge

### 1A: ServiceNow ITSM Product Knowledge

**What this document is:** A ServiceNow Solution Design and Architecture Document (SDD) — a client-facing configuration specification that defines exactly how each ITSM module will be set up for a specific client. It is NOT a generic ServiceNow guide — every table, every list, every configuration decision is client-specific or confirmed OOB standard.

**Modules and capabilities:**

**Incident Management** — Manages any disruption to a service or workflow. Key configurable elements: category/subcategory taxonomy, priority lookup matrix (Impact × Urgency → Priority), on-hold reason codes, SLA definitions (Response + Resolution per priority), assignment groups, resolution codes, email notification events, channels, reports, dashboards.

**Problem Management** — Identifies root causes of recurring incidents. Shares category taxonomy with Incident. Key elements: problem states (New → Assess → Root Cause Analysis → Fix in Progress → Resolved → Closed), cause codes, resolution codes, problem task configuration.

**Change Management** — Controls all production environment changes. Three types: Normal (requires `<customer name>` + Business + CAB approval), Standard (pre-approved, no deviation), Emergency (post-hoc CAB review). Requires two plugins: `com.snc.change_management.risk_assessment`, `com.snc.change_management.cab`. Default tasks on Implement: "Implement" + "Post-implementation testing".

**Service Level Management (SLM)** — Defines and tracks SLAs (external), OLAs (internal), and UCs (external provider contracts). SLA notifications at 50%, 75%, and breach. SLA conditions: Start, Pause, Stop, Reset. Retroactive start option available.

**Knowledge Management** — Shared knowledge base with article lifecycle: Draft → Review → Published → Pending retirement → Retired. Two OOB KBs: IT (Service Desk) and Knowledge (open read; Knowledge-role users contribute). Feedback task states: New / Work in progress / Awaiting information / Resolved / Closed.

**Service Portal** — Client-facing self-service portal. Section exists in SDD as heading; body content is per-engagement.

**Service Catalog and Request Management** — Self-service catalog with OOB catalogs: Services, Can We Help You?, Office, Hardware, Peripherals, Software, Desktops, Mobiles. Service Request states differ from Incident states. Catalog Roles (catalog_admin, catalog_manager, catalog_editor, etc.) are separate from Request Roles.

**Release Management** — Plans and tracks IT releases. States: Draft / Scoping / Awaiting Approval / Work in Progress / Testing/QA / Deploy/Launch / Close Complete / On Hold / Cancelled. Phases: Requirement Gathering / Design / Development / Build / Deployment / QA / User Acceptance. Types: Major / Minor / Upgrade / Emergency / Maintenance / Patch.

**Integrations:**
- Azure AD/SSO: HTTPS port 443 inbound; single sign-on + user provisioning
- Jira: HTTPS port 443 bi-directional; Epics and Stories sync
- SolarWinds: HTTPS port 443 bi-directional; events create Incidents
- GitHub: in scope but details per-engagement

**Critical OOB vocabulary (must be reproduced verbatim):**
- Priority: `1 - Critical`, `2 - High`, `3 - Moderate`, `4 - Low`, `5 - Planning`
- Impact: `1 – High`, `2 – Medium`, `3 – Low` (en-dash, not hyphen)
- Urgency: `1 - High`, `2 - Medium`, `3 - Low`
- On-Hold reasons: `Awaiting Caller`, `Awaiting Change`, `Awaiting Validation`, `Awaiting Vendor`
- Plugins: `com.snc.change_management.risk_assessment`, `com.snc.change_management.cab`

def add_heading(doc, text, level):
    """Add a Word heading at the given level."""
    p = doc.add_heading(text, level=level)
    return p

def add_body(doc, text, style="Normal"):
    """Add a body paragraph."""
    p = doc.add_paragraph(text, style=style)
    return p

def add_bullet(doc, text, style="List Paragraph"):
    """Add a bulleted paragraph."""
    p = doc.add_paragraph(style=style)
    p.add_run(text)
    return p

def add_image(doc, img_filename, width_inches=5.5):

def add_table(doc, headers, rows, style="Formatforthetable1"):
    """Add a formatted table with colored header row."""
    table = doc.add_table(rows=1+len(rows), cols=len(headers))
    
    # Try to apply table style; fall back to TableGrid if style not found
    try:
        table.style = style
    except Exception:
        table.style = "Table Grid"
    
    # Header row — bold, white text, red fill (#E31837)
    header_row = table.rows[0]
    for i, header_text in enumerate(headers):
        cell = header_row.cells[i]
        cell.text = header_text
        # Style the header cell
        run = cell.paragraphs[0].runs[0] if cell.paragraphs[0].runs else cell.paragraphs[0].add_run(header_text)
        run.bold = True
        run.font.color.rgb = RGBColor(0xFF, 0xFF, 0xFF)
        # Set fill color
        tc_pr = cell._tc.get_or_add_tcPr()
        shd = OxmlElement('w:shd')
        shd.set(qn('w:val'), 'clear')
        shd.set(qn('w:color'), 'auto')
        shd.set(qn('w:fill'), 'E31837')
        tc_pr.append(shd)
        cell.paragraphs[0].alignment = WD_ALIGN_PARAGRAPH.CENTER
    
    # Data rows
    for r_idx, row_data in enumerate(rows):
        row = table.rows[r_idx + 1]
        for c_idx, cell_value in enumerate(row_data):
            if c_idx < len(row.cells):
                row.cells[c_idx].text = str(cell_value)
    
    return table
